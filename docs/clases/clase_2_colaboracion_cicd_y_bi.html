Bloque 4 · Colaborar

Chico se revisa. Grande se aprueba sin leer.

Un PR de tres archivos se revisa en cinco minutos y encuentra cosas. Uno de cuarenta archivos recibe un LGTM y no lo miró nadie.

La prueba del "y"

Si para describir tu PR necesitás la palabra y —"agrego la métrica de margen y corrijo el ticket promedio"— probablemente son dos PRs.

El objetivo de revisar no es controlar a nadie. Es que haya siempre una segunda persona que entienda cada cambio.

Bloque 4 · Colaborar

Qué nunca se versiona

Jamás

Credenciales

Usuarios, contraseñas, connection strings, tokens, claves de API.

Si se sube una vez, queda en el historial para siempre, aunque después la borres. Hay que rotarla, no borrarla.

No conviene

Artefactos generados

Exportaciones, CSV de salida, cachés, todo lo que se puede volver a producir.

Ocupan, generan conflictos imposibles de resolver y no aportan historia.

# .gitignore
.env
credenciales.json
/salidas/
*.csv

.gitignore es el archivo que le dice a Git qué ignorar. Se define al empezar, no cuando ya pasó.

Ejercicio 4 · 20 minutos

Provocar un conflicto

git checkout develop
git merge feature/ticket-sin-internos   # entra sin drama
git merge feature/ticket-redondeado     # ✗ conflicto

Las dos ramas cambian la misma línea. Ninguna está mal. Git no puede decidir cuál gana — y no debería.

Resolver un conflicto es decidir. No es un error ni algo que hiciste mal: es Git avisándote que dos personas tomaron decisiones distintas sobre lo mismo.

Bloque 5 · CI/CD

Dos ideas, no una herramienta

CI · Integración continua

Validar cada cambio, automáticamente

Cada vez que alguien propone un cambio, algo lo revisa solo: que respete las convenciones, que no rompa lo que andaba, que no traiga una credencial.

Te enterás ahora, no en tres semanas.

CD · Entrega continua

Promover el cambio entre ambientes

Que pasar de desarrollo a pruebas y de pruebas a producción sea un procedimiento automático y repetible, no una secuencia de pasos manuales que alguien recuerda.

Jenkins, GitHub Actions, Azure Pipelines, GitLab CI son herramientas que implementan esto. La idea es anterior a todas ellas.

Bloque 5 · CI/CD

El quality gate

Un conjunto de verificaciones automáticas que un cambio tiene que pasar para poder mergearse. Si no pasa, el botón de merge queda bloqueado.

El del repositorio de hoy valida cuatro cosas:

VerificaPor qué
Nombres en snake_caseConsistencia: que nadie tenga que adivinar cómo se llama un archivo
Encabezado de metadatos completoQue toda métrica tenga dueño identificable
Sin credenciales embebidasLa red de seguridad ante el descuido
Sin artefactos generadosQue el repositorio no se llene de basura

Por qué frenar el merge y no sólo avisar: una advertencia que no bloquea se ignora. Siempre. La primera vez con culpa, la décima ya ni se lee.

Bloque 5 · CI/CD

Una historia real, de esta misma semana

El quality gate de este repositorio se escribió en una Mac. Corría perfecto:

QUALITY GATE: OK

Al subirlo, CI —que corre en Linux— falló en trece verificaciones. El motivo: grep en macOS acepta un patrón que empieza con --, y el de Linux lo interpreta como fin de opciones. El chequeo nunca se estaba aplicando.

Funcionaba en la máquina de quien lo escribió y no funcionaba en ningún otro lado. Eso es exactamente lo que CI existe para atrapar: «en mi máquina anda» deja de ser un argumento.

Ejercicio 5 · 20 minutos

Hacer fallar el gate, y un hotfix

Primero rompelo a propósito: sacale el campo -- dueño: a tu métrica y corré la validación. Después agregá una línea con una contraseña falsa y volvé a correrla.

git checkout main
git checkout -b hotfix/1.0.2-tu-nombre   # ojo: de main, no de develop

Corregís algo, y abrís dos PRs: uno a main y otro a develop.

Para pensar: ¿qué pasa si te olvidás del segundo?

Bloque 6 · Cierre

Y esto qué tiene que ver con Power BI y Qlik

Todo. Lo que vimos es el flujo. Lo que cambia en cada herramienta es sólo qué archivo se versiona.

Power BI

El formato PBIP guarda el informe como carpeta de archivos de texto, en lugar de un .pbix binario. Texto es lo que Git sabe comparar.

Qlik

Los scripts de carga se extraen a archivos .qvs, que también son texto y también se versionan.

El cómo de cada una —PBIP, fabric-cicd, Deployment Pipelines, extracción de scripts, herramientas de terceros— es el tema de la próxima capacitación, específica por herramienta.

Bloque 6 · Cierre

Si te llevás cuatro cosas

  1. Git guarda cambios, no copias. Por eso puede responder qué, quién, cuándo y por qué.
  2. Las ramas existen para no pisarse. GitFlow sólo pone nombres y reglas a algo que ya necesitabas.
  3. Si toca main, toca develop. Release y hotfix siempre son dos merges.
  4. Lo que no bloquea, se ignora. Por eso el quality gate frena el merge en vez de sólo avisar.

El repositorio queda disponible para practicar. Los ejercicios se pueden repetir todas las veces que haga falta.
